3. Input Validation & Security Guardrails

Defensive engineering practices adhering to Section 4.1

Multi-Stage File Verification
  • MIME & Magic Bytes: Verifies `%PDF`, `\xff\xd8\xff`, `\x89PNG`.
  • Page Limit Enforcer: Enforces strictly ≤ 3 pages. Rejects > 3 pages with `EXCEEDS_PAGE_LIMIT`.
  • Corruption & Tamper Check: Tests parser load and raises `CORRUPTED_PDF` without crashing.
Security & Error Contracts
  • No Secrets in Code: Environment variable injection via `.env`.
  • Standardized Error Responses: Strict Section 5.3 compliance `{"error": {"code": "...", "message": "..."}}`.
  • Safe Disk Handling: Sanitized timestamps and filenames to prevent path traversal attacks.

5. Financial Validation & Accounting Rules

Section 4.4 Financial integrity and arithmetic verification

Validation Checks Executed
  • Invoice: Quantity × Unit Price ≈ Line Total; Sum of line items ≈ Subtotal; Subtotal + Tax − Discount ≈ Total (including GST-inclusive).
  • Balance Sheet: Total Capital & Liabilities ≈ Total Assets; Component sum checks.
  • Profit & Loss: Total Income, Total Expenditure, Net profit before minority, Consolidated profit, Appropriations.
  • Cash Flow: Operating + Investing + Financing + FX ≈ Net Change; Opening + Net Change ≈ Closing.
Robust Edge Cases Handled
  • Bracketed / Negative Numbers: Parses `(45,000)` → `-45000.0`.
  • Missing Fields Handling: Returns `NOT_APPLICABLE` rather than assuming or inventing zeros.
  • Numerical Tolerance: Configurable tolerance (≤ 0.05) to accommodate standard currency rounding.
